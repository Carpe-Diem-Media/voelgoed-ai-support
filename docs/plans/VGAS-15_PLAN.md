## Lifecycle and lock boundaries

| State or stage | Guard, effect and terminal behavior |
| --- | --- |
| QUEUED → RUNNING (T02) | Current qualified session, permission, pinned revision and epochs, eligible batch, no blocking UNKNOWN delivery and admission/capacity under lock. Increment claim and schedule bounded recovery. Preserve root turn ref and absolute deadline. |
| RUNNING, evaluate | Read public context outside a transaction. Classify safe deterministic paths first. Qualify before rank and every paid attempt. An in-flight attempt owns a one-shot marker and hold. No locks during external I/O. |
| RUNNING → COMPLETED (T04/T05) | Same claim, watermark, coverage, live evidence, mode and current cutoff under locks. Atomically persist typed decision + permitted intent/jobs or explicit no-send. Local handoff advances epoch/inhibits, fences pending work and records its own operational deadline. COMPLETED is immutable and terminal. It says nothing about remote acceptance. |
| RUNNING → SUPERSEDED/CANCELLED/FAILED | Late input carries unanswered coverage into one bounded successor with the original turn budget/deadline. Stale authority cancels. Exhaustion/permanent failure uses authorized local handoff or audited staff triage. These states are terminal. Existing RETRY_WAIT remains bounded to proven-safe recovery. |
| PENDING → SENDING → SENT/UNKNOWN/CANCELLED/FAILED (T06) | Separate delivery fence/lease and fresh Chatwoot checks. Resolve live evidence again in final authorization. Definite pre-entry denial can cancel. Ambiguity holds and blocks replay. SENT requires positive qualified acceptance. UNKNOWN can reconcile or be closed by an authorized operator with uncertainty preserved. |
| Attempt/reservation (T03/T08) | Pending claim → RUNNING/RESERVED → SUCCEEDED or FAILED/SETTLED with trusted usage, REJECTED/RELEASED on proven no charge, or UNKNOWN/UNKNOWN. Trusted late evidence may settle UNKNOWN or correct a conservative charge once. Neither recovery nor correction confers answer permission. |

Preserve control → assistant → binding → sessions → runs → deliveries (`configuration.ex:412–418`, `delivery.ex:101–130`). In financial work lock attempts, reservations and windows after the qualified support rows, using the shared day-then-month order. Re-sample time after lock wait and after evidence SQL, with a strict cutoff. Concurrent evidence changes serialize on the control lock. There is a residual race from final local authorization commit to an external POST. Neither local locks nor hashes make Chatwoot status, ownership and write atomic. There is also a dispatch-marker-to-wire crash window for calls. Conservatively retain UNKNOWN when execution cannot be excluded. The new workflow permits synthetic writes only for dispatch proof.
