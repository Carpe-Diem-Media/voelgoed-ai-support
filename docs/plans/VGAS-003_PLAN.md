**Goal.** Let staff review and publish source-verified bilingual FAQs. Give the support worker a bounded evidence manifest restricted to its current scope.

**Architecture.** Knowledge owns the editorial snapshot, publication pointer and derived index. Intelligence owns revision grants and inference attempts. Governance admits and settles each embedding call. Use authorised Ash actions around short PostgreSQL transactions and Oban jobs. Keep transport outside transactions.

Proposed file ownership follows `lib/voelgoed_ai/{knowledge,intelligence,governance}/` and the existing domain modules. Recheck the staff session generation and current role under the staff lock on every staff operation. Limit private persistence actions to the owning transaction with a resource/action-bound capability. ### KnowledgeCollection and AssistantKnowledgeGrant

- `knowledge/knowledge_collection.ex`. Store unique slug, name, public/internal audience, status and security epoch. Keep audience immutable in this slice. ADMIN creates, enables, disables or retires. Editor/reviewer projections require collection scope. A support worker sees collection eligibility only through the bounded evidence action. Require valid configuration on enable, bump epoch on permission change and check the captured epoch when resuming queued publication or using previous evidence.
- `intelligence/assistant_knowledge_grant.ex`. Store restrictive FKs to AssistantRevision and KnowledgeCollection and unique pair. ADMIN can grant or remove on a draft only, under the owning assistant lock and a collection eligibility check. Reject internal grants to the public assistant. Approved assistant publication freezes grants and includes the sorted grant set in the new configuration hash version. Keep historical hashes and existing fixed-reply revisions interpretable. Extend the existing AssistantRevision draft actions and `Support.Configuration` publication path only where needed. Validate the set again at assistant publication, commit the assistant pointer and restrictive epoch/fence with it, and preserve the predecessor's fixed-reply configuration rules. Empty grants yield empty knowledge access. A scoped action may resolve only the grants needed by a worker's own purpose. No mutation when the assistant revision leaves draft.

| Collection | DISABLED → ACTIVE | ADMIN enables valid scope. Use a fresh epoch. |

- `knowledge/article_revision.ex` and bounded types under `knowledge/`. Store creator, approval and publishing request actor references, approval and publication times, hash, expected previous pointer, publication generation, active index generation/profile when applicable, reason, correlation and bounded deadline for active work. Locale content contains title, alternative questions, approved answer, ordered steps and escalation conditions. Source refs contain kind, stable ref, version/date where known and separately approved public link. Store no customer PII. Validate unique locale keys and presence of primary locale, immutable reviewed content, time-sensitive expiry, and `effective_from < expires_at` when expiry exists. Convert explicitly entered SAST dates to UTC. Review date is advisory.
- Version the SHA-256 input. Encode an ordered, typed structure with fixed field order, sorted set-valued scope and locale keys, and declared text/UTC normalization. Preserve meaningful list order and exact approved answer text. Include scope, source metadata, modes and validity. Keep review, transport and publication metadata outside the content hash. Recompute at submit, approve and publication checks. Use equality against the submitted hash when reviewing so a stale screen cannot approve a different snapshot.
- Extend `governance/audit_event.ex` with explicit knowledge targets, state transitions and staff/scoped worker policies. Commit consequential audit events with their writes. Log safe IDs, versions, UTC times, reason codes and correlation. No payloads, private source text, vectors or provider errors. Keep aggregate accounting reads separate from editorial access.

| Action | Actor and transition | Guard, side effect and failure |
|---|---|---|
| `create_draft`, `edit_draft` | E creates/edits DRAFT | Scoped active article. Validate bounded input and compare the editor's version/hash for stale saves. No jobs or calls. |
| `submit_review` | E, DRAFT → IN_REVIEW | Require source, locale, scope and dates. Freeze review hash. |
| `request_changes` | R, IN_REVIEW → DRAFT | Require reason and match reviewed snapshot. Clear attestation/hash used for review. |
| `approve` | R, IN_REVIEW → APPROVED | Attest exact hash and source, audit any authorised low-risk self-approval. Keep unresolved sensitive policy outside automatic answer eligibility. |
| `request_publish` | R, APPROVED → PUBLISHING | Revalidate approval, active public scope, valid profile and effective-time window. Compare the expected current pointer approved for the request with the current article row. Capture collection epoch, pointer and generation. Atomically create work rows and jobs for every approved locale. A future start stays APPROVED. Enqueue failure rolls back. |
| `publish_ready` | P, PUBLISHING → PUBLISHED | Only the purpose-scoped publisher finalises. Verify current scope/epoch/time, matching request fence, all and only the approved locale rows READY for the same generation/hash/profile and unchanged expected pointer. Under article lock supersede the old PUBLISHED revision first, publish the candidate and switch pointer in one T07 commit. Async duplicate becomes a no-op. A competing pointer change yields a typed conflict, with no automatic rebase or activation. |
| `fail_publication` | P or scoped recovery, PUBLISHING → PUBLISH_FAILED | Exhausted safe attempts, stale request, deadline or unrecoverable index evidence. Invalidate pending generation, keep the old pointer only subject to all live eligibility checks. |
| `retry_publication` | R, PUBLISH_FAILED → PUBLISHING | Reaffirm the immutable approval and verify current scope/profile/time. Explicitly confirm the latest expected pointer, allocate a different generation and enqueue atomically. A new attempt shares the configured parent bound where it applies. |
| `revoke` | R, APPROVED/PUBLISHING/PUBLISH_FAILED/PUBLISHED → REVOKED | Audit reason, invalidate queued generation, clear pointer if owned. Preserve spend and its evidence. |
| `expire` | scoped scheduled worker, PUBLISHED → EXPIRED | Trusted time reaches expiry. Clear pointer if owned and invalidate evidence. Retrieval reads the clock even if this job is late. Race with replacement resolves under the article lock. |
| `withdraw` | E/R, DRAFT/IN_REVIEW → WITHDRAWN | Scoped, deliberate abandonment with reason. |
| `supersede` | P, PUBLISHED → SUPERSEDED | Only inside successful T07. |
| `archive` | R, Article ACTIVE → ARCHIVED | In the same transaction clear pointer, revoke current and approved/pending publications, invalidate their jobs, and make remaining drafts inaccessible to transitions. History remains readable only to authorised staff. |

SUPERSEDED, EXPIRED, REVOKED and WITHDRAWN are terminal. ARCHIVED and RETIRED are terminal. Restore archived content through a new article. Restore prior wording on an active article through a new revision with current source review and approval. A restriction change fences unsent work through live validation. A late worker may settle its cost, but its result cannot mutate a stale index or restore access.

### Embedding profile and ArticleEmbedding

Use one code-versioned profile with provider/model, 1536 dimensions, cosine, serialization version and ID/hash. Candidate `openai:text-embedding-3-small`, run through deterministic transport in local/CI. Canonical embedding input is a separate bounded locale projection of title, alternative questions, approved answer and necessary approved scope. Exclude private source refs and PII. Validate nonempty input, one locale per request, finite representable float32 vector, exact dimension and nonzero norm. Separate derived rows are justified by locale-level claims and recovery, concurrent variant completion, and same-profile reindex without overwriting the currently active generation.

`knowledge/article_embedding.ex` stores revision FK, locale, profile, content hash, generation, state, vector (nullable), attempts, last attempt/fence reference and error code. Enforce one row per `(revision_id, locale, generation)`, a consistent hash/profile for the parent request, and READY iff a valid vector exists in the row. Invalidation may drop the vector. A partial/unique attempt identity and locked conditional transitions give duplicate workers one winner. Oban uniqueness is supplemental. Jobs carry internal row IDs. Reload locale, canonical text and all authority from rows.

| State change | Actor, guard and effect |
|---|---|
| MISSING → QUEUED | Publisher request creates the row once for this approved variant and generation, with durable enqueue. MISSING can be represented by absence before this transaction. |
| QUEUED → RUNNING | V locks the intended row and validates scope, deadline and content. Atomically claim and reserve an inference attempt. Duplicate execution does not reserve or invoke again. |
| RUNNING → READY | V records the fenced valid vector only after verified result/usage, with atomic accounting where the result is applied. If all locales are ready, enqueue finalisation in that transaction. |
| RUNNING → FAILED | V records a typed error and accounts for charge or uncertainty. Exhausted/permanent/ambiguous work fails the publication. Other independently eligible revisions can remain available. |
| FAILED → QUEUED | V or scoped recovery only after verified no-effect or pre-call transient failure, within explicit attempt and deadline bounds. Fresh inference ID per invocation. Configure Oban to retry local storage work only when the durable claim permits it. |
| Any → INVALIDATED | V/P or the relevant lifecycle action fences a stale/cancelled generation. Terminal for that generation. Never reuse it. |

Use a durable completion check and bounded Oban recovery for expired claims and stranded finalisation. If one locale fails publication, fence its siblings in the same generation. A sibling with a committed dispatch can still account for the outcome without storing eligible content. Give retries and stale-claim recovery a finite persisted deadline and maximum ordinal. Record the synthetic values in the test configuration, and keep real work disabled until the owner approves limits. Duplicate finalisation and replay of processed Oban jobs are safe. Do not enqueue from an edit or approval. For safe same-profile reindex, the reviewer explicitly starts a derived generation for a still-valid published revision. Build it beside the old index with the same admission rules. Compare the current pointer/hash/profile/collection epoch and old active generation before a publisher atomically switches the active generation. Invalid or incomplete candidates leave the old generation only while it remains eligible. A scoped reviewer can request index rollback. The publisher can switch to a retained, evaluated generation of the same still-current approved revision if all guards hold. Revocation/expiry/archive invalidates both. A content rollback requires a new approval. Cross-profile cutover needs a later evaluated migration and owner approval. Restore databases with live gates off, reapply revocations and confirm index and unknown-spend state before re-enable. Do not replay an ambiguous call from restored jobs.

- `governance/usage_reservation.ex`. One unique reservation per inference attempt. Require one settlement per reservation and distinct audited correction keys. Enforce parent consistency across ledger and reservation with a composite FK or equivalent reviewed constraint. V/S settle only their own invocation and Q reconciles bounded records under its own scope. ADMIN can read limited aggregates, with no general read/write capability.
- Use governance budget windows keyed by kind, scope and UTC start, with a unique key, nonnegative totals and overflow checks. Initially use global day/month caps for both embedding purposes. Under the global control lock, lock or create the ordered windows and check projected settled spend plus outstanding reserved spend plus unresolved older-window risk against both caps. Count each outstanding reservation at most once per cap. Count unresolved RESERVED and UNKNOWN amounts across rollovers until resolved. Settle to origin windows even after rollover. Enforce this across reserve, settlement, release and correction so concurrent rollover cannot erase exposure. Make current admission conservative when price/cap is absent or invalid. Use synthetic fixture caps, with operational caps and estimates awaiting approval.
- Reserve pessimistically from a provider-verified finite input bound and frozen price snapshot. Local fakes use a versioned price fixture. Store quantities and rates with explicit units and use integer arithmetic with conservative ceiling on fractional nano-USD, wide intermediates and checked bigint writes. Compute actual from trusted integer usage units at the snapshotted rate. Ignore adapter-estimated floating cost. Accept actual above the reserve when verified, record the discrepancy and inhibit admission when exhausted. Use a typed inhibit/alert for discrepancies or overflow that cannot be represented safely, retain the hold and preserve human routing.
- Use a single owned embedding entry point. Claim plus reservation commits before any invocation (T03). At the transport boundary, a second short guarded transaction consumes the one-shot dispatch fence, rechecking eligibility, gate, deadlines and claim generation. Only its winner can invoke. The request uses fixed model, host and options, one bounded UTF-8 input, receive and total timeout bounded by remaining deadline, `redirect: false`, and `req_http_options: [max_retries: 0, ...]`. Run the HTTP call after commit. Keep the candidate adapter disabled by default, even with a key present. A missing/disabled gate denies before transport. Synthetic mode uses the same claim and accounting with a fake wire boundary and no network.
- F04's Ash AI adapter can be used for one input with a guarded Req transport wrapper if the wrapper preserves reliable status, usage, request correlation and single-attempt controls. If this cannot be demonstrated, use the narrow G021 fallback `ReqLLM.embed/3` with `return_usage: true` and a controlled Req adapter for correlation and failure classification. `return_usage` alone does not supply a request identifier or useful failure-usage evidence. Validate the correlation, model and usage of the specific attempt. Fail closed if the actual cost is uncertain, including malformed/missing usage. Keep all redacted provider evidence local to the attempt. Verify actual wire hits below the wrapper because replacing the adapter with a fake Plug can hide retries from wrapper counters.

| Contract | Transition and atomic effect |
|---|---|
| Attempt enqueue | Scoped S/V create QUEUED within parent and purpose bounds. No reservation and no call on queue. |
| T03 admission | QUEUED → RUNNING with RESERVED, locked budget admission and generation/dispatch fence. If denied, durably cancel or return a typed denial without partial reserve. Revalidate the parent before dispatch. |
| Definite no-effect | QUEUED → CANCELLED before dispatch. A pre-dispatch RUNNING attempt that is provably unsent, or a verified provider non-execution, can become REJECTED with RELEASED. Release only from reliable no-charge evidence. |
| Trusted result or failure | RUNNING → SUCCEEDED for valid result + actual usage, or FAILED for definite failure and known charge. T08 atomically moves RESERVED → SETTLED, appends one ledger entry, updates origin totals and records attempt outcome. Failure to use a now-stale result does not erase the charge. |
| Ambiguity | Timeout/reset, post-dispatch crash, missing usage or inconclusive outcome moves RUNNING → UNKNOWN and RESERVED → UNKNOWN. Keep held across TTL, rollover, restart and reindex. Recover stale unconsumed dispatch only if the claim is atomically fenced and absence of invocation is proven. No automatic retry after possible execution. |
| Reconciliation | Q uses reliable evidence to move UNKNOWN to SUCCEEDED/FAILED with SETTLED or REJECTED with RELEASED. For an authorised conservative closure move to ABANDONED with CONSERVATIVELY_SETTLED at the held ceiling. No automatic closure. Terminal corrections append a linked audited entry and adjust totals under the same windows. |
| Duplicate or stale settlement | Compare attempt ID, one-shot fence and stable evidence identity. Duplicate returns the durable result. Conflicting evidence goes to reconciliation. Terminal attempts never re-run. No exception path from a payment/settlement failure starts another invocation. |

## Authorised retrieval and evidence

1. `Knowledge.search_published` accepts a bounded minimised query and requested locale through the trusted support actor on a qualified SupportRun. Resolve the run, binding, session, assistant and pinned revision from storage. Apply current control, ownership and epoch, enabled binding/assistant, public ceiling, current published assistant revision/grants and deadline. Reuse the predecessor's stricter exact current pin where it applies. If the pin is ever permitted to remain historical, require intersection with live grants. Stop on unresolved scope or missing applicable public grants before query embedding. No raw query, customer identity, notes, provider options or scope in durable work arguments.
2. Get the matching, admitted query vector through the same inference boundary as article indexing. Keep it in memory, tied to the exact query/profile/attempt. Invalid query/vector, unavailable provider or accounting denial gives typed no-evidence/unavailable. Do not silently use lexical-only results on failure. A lexical-only hit after a successful query embedding remains a legitimate ranking branch.
3. In `knowledge/retrieval.ex`, use one parameterised SQL statement called inside the authorised action. Build a shared eligible candidate CTE before ranking. Join the run's pinned and current grants, active collection with public audience, active article and its exact current published revision, requested locale, applicable typed scope, validity at trusted UTC, and READY active-generation variant with matching revision hash and selected profile. Explicitly qualify the scope and compare the live epochs used to authorise the action. Use the same predicate for both branches and for projection. Treat missing or ambiguous requested scope as ineligible for scoped content. No search path can accept an arbitrary collection, foreign run ID or an externally supplied vector as authority.
4. Rank eligible rows on exact pgvector cosine distance (`<=>`, ascending) and PostgreSQL `simple` FTS (`@@` then `ts_rank`, descending). Search approved title, questions and answer only. Use bound text parameters and a bounded tokenised query. Use F05's quoted lexeme disjunction as the starting lexical treatment. Treat malformed/empty token input as no query. Sort both branches by native UUID as final key and take ten each. Fuse using reciprocal-rank fusion with k=60 and missing-branch contribution zero. Dedupe by revision, sort descending fused score then ascending native UUID and return at most four. Use exact rational comparison or equivalent stable arithmetic for fused ties. Keep ranks/scores in redacted internal evidence only. F05's orthogonal-vector fixture behaviour does not set a production cutoff. Calibrate relevance/failure with versioned fixtures and staff evidence. Top rank or positive similarity alone confers no answer eligibility.
5. Return a bounded typed manifest. Include run ID, article/ref and revision IDs, approved locale, content hash, profile and generation, current scope/collection and epochs for revalidation, response mode, relevant approved text/steps within size limits and allowlisted public links. Keep internal source references and ranking metadata out of the content projection. For ESCALATE_ONLY expose routing classification with no substantive answer. EXACT needs the requested approved variant, or a safe offer of another approved locale or handoff. Unknown, insufficient or conflicting evidence returns clarify/handoff. Keep semantic adjudication for GROUNDED replies in the later workflow.
6. `validate_evidence` takes the exact manifest references, re-derives scope and all eligibility and matches hash, locale, profile and generation against current rows. Reject forged, missing, revoked, expired or superseded references and links outside the current allowlist. Recheck at decision and immediately before any future evidence-bearing send, using the same predicate under the upstream lock order. VGAS-003 delivers and tests this boundary with synthetic manifests. VGAS-004 wires it to evidence-bearing decisions/delivery. Existing fixed-reply delivery stays on its established path. A change committed before a later validation must deny. The database cannot make a later remote send atomic with that validation.

## Transaction and lock order

Use the inherited order **staff → control → assistants by ascending ID → binding → sessions → targets → counter windows**. Read immutable routing IDs without locks only to discover parents. Verify the joins again under the locks. Never go back to an earlier tier within the transaction.

- Scope and assistant-grant changes take staff, global control and the owning assistant in that order, then assistant revision, collections and grant rows in the target tier. Reuse the owning assistant lock in `support/configuration.ex` when touching draft grants or the assistant current pointer.
- In the target tier retain the existing support target order, with runs and deliveries before knowledge rows when a path needs both. Then take collections by ID, articles by ID, revisions by ID, embeddings by ID, inference attempts, reservations and ledger entries. Grant operations acquire collection rows before grant rows. Within each group sort ascending ID. Queries for a future send take knowledge locks after the delivery target, never before acquiring session/support targets. Bulk import and archive use the same parent-before-child order.
- Editorial transitions lock staff first, then control and relevant targets. Worker T07 takes control and the publication targets. Query embedding and evidence checks take control, assistant, binding and session before support and evidence targets. Article embedding takes control, then the knowledge and inference targets. T03/T08 add spend windows last, in fixed kind/scope/start order, including old origin windows. Serialize cross-window risk with the global control lock. Keep existing admission counters in their inherited order and avoid acquiring either family after holding a later window. A worker does not acquire a staff lock after control. A durable approved publication request is its own scoped authority, subject to current article, collection and generation fences.
- Use explicit `Repo.transact/1` boundaries and locked or compare-and-set writes. Never hold locks during transport. Defer retries until durable state allows them. Prove lock compatibility with two or more real connections and forced orderings. Treat a lock timeout or missed fence as a typed failure requiring fresh authorised work, never as permission to continue.
