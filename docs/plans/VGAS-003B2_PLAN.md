# VGAS-003 B2 implementation plan

B2 completes guarded article publication, same-profile index maintenance, and the authorised knowledge and evidence actions. Knowledge owns the publication pointer and evidence. Intelligence owns embedding attempts. Governance accounts for both embedding purposes.

Plan against PR #11 at `6dce3efed3e75cc8d9a8a89f4791254031950b32`. Branch B2 from updated `origin/main` after B1 merges. Compare the merged B1 diff, migrations and live VGAS-14 prerequisites before implementing. The accepted VGAS-003 plan and its orchestrator addendum govern alongside G003, G006, G014–G019, G021, G026–G030, resource contracts T03/T07/T08, and amendments A-008/A-010/A-011. B2 uses Phoenix 1.8.17, Elixir 1.20.5/OTP 29.1.2, and PostgreSQL 18 with pgvector. Keep PR C routes and LiveView, VGAS-004 support wiring and generation, live calls, operating prices/caps, and deployment outside B2.

Failure fences the pending rows and clears the pending flag, preserving the old index subject to live eligibility. Retain at most one prior complete generation per current revision as the proposed storage bound. Keep generation allocation monotonic across rollback.
- [ ] Record a rollback request as a scoped audit event and enqueue its ID in the same transaction. The publisher's specific `rollback_index(request_id)` action reloads that request and checks its deadline, current pointer, approval/hash/profile, collection epoch, expected active generation/epoch and absence of a pending reindex. A reviewer-supplied flag or READY status confers no evaluation. Absent a qualifying receipt, deny rollback. Successful rollback switches the active index and increments the epoch without embedding or changing approved content. Replay after any switch is stale, including a switch back to the same generation.

## 3. Rank and revalidate evidence

- [ ] Keep one private parameterised eligibility query in `knowledge/retrieval.ex` under the authorised boundary. Join pinned and live assistant grants, an ACTIVE public collection, ACTIVE article, exact current PUBLISHED revision, requested approved locale and READY row of its active generation, matching hash/profile. Always apply `effective_from <= now` using trusted UTC. Require `now < expires_at` when expiry is present. For each nonempty brand/product/event/service restriction require a verified matching context value. Missing or ambiguous scope fails closed. Require low-risk modes allowed by section 6. Use the same predicate for preflight, ranking, projection and validation. During ranking, qualify the run again after the transport and use one statement with a shared eligible CTE before either branch limit.
- [ ] Rank exact cosine distance ascending with `<=>`. In the lexical branch use `simple` FTS over approved title, alternative questions and answer, with F05's disjunction of quoted lexemes derived from bounded input, then `@@` and descending `ts_rank`. Treat malformed/empty tokens as no query. Tie-break each branch by native revision UUID and take ten per branch. Fuse one-based ranks with RRF `k=60`, zero for an absent branch. Compare exact fractions by cross multiplication, deduplicate on revision UUID, break fused ties by UUID ascending and return at most four. F05's fixture distance filter supplies no production cutoff. A lexical hit can contribute after a successful query embedding. [PostgreSQL text search](https://www.postgresql.org/docs/18/textsearch-controls.html)
- [ ] Project only bounded approved text/steps and currently allowlisted stored links. Include run/claim, article/revision/ref, locale, content hash, mode, profile, generation, index epoch, collection/epoch and qualified scope/epochs. Use the existing content field limits and preserve complete exact-answer text or omit that candidate. Keep internal source refs, vectors and scores out of the projection. An absent exact locale or unresolved evidence yields safe no-evidence or handoff. Ranking provides candidates only. VGAS-004 owns semantic coverage, conflict handling and decision rendering.
- [ ] In `validate_evidence`, accept bounded citation IDs and used links against the server-owned manifest issued in the authorised flow. Bind that manifest to the internal capability in B2 tests. Reject empty substantive citations, duplicates, foreign or unissued references even if independently public, and any changed scope/epoch/locale/hash/profile/generation/index epoch. Rebuild current eligibility and permitted links. Return only current approved evidence for those exact references, or deny the whole selection. Revalidation makes no provider call. VGAS-004 must requalify at decision and immediately before an evidence-bearing send, under the upstream delivery lock order. A change committed before validation denies. A later remote send cannot be atomic with the local check.

## Orchestrator addendum (accepted with changes, 2026-11-26)

The orchestrator reviewed this plan against `docs/plans/VGAS-003_PLAN.md` (AC1–AC3, the PR B checklist, and the T07/reindex/rollback and retrieval sections) and accepts it with these changes.

1. **Split B2 into two serial PRs.** Each owns one migration in the chain and must be independently green.
   - **B2a, publication and index maintenance:** sections 1 and 4 (publication schema part), the `FinalizePublication` and `ExpirePublication` workers, recovery sweep extension, revoke/archive/expire of PUBLISHED revisions, reindex and evaluated index rollback, and their tests. Migration `vgas_003b2a_publication`.
   - **B2b, query accounting and retrieval:** sections 2 and 3, the `InferenceRun` query purpose (section 4, query part), the admission-before-spend lock test, and their tests. Migration `vgas_003b2b_retrieval`. B2b branches from merged B2a.
2. **TEST-only gates.** Like the B1 embedding gate, the support-capability fixture issuer and the synthetic rollback evaluation receipt compile only in TEST. Every other build denies search and index rollback. Do not add any configuration source that could enable them.
3. **No support wiring.** `RunProcessing` must not call retrieval or validation. B2b may reuse its qualification helpers read-only. If that needs a change to `RunProcessing`, keep it to an extracted read helper with no behaviour change, and test that the fixed-reply path is unchanged.
4. **Evaluation record storage.** Keep the rollback evaluation record minimal (generation, hash, profile, evaluator kind, time), with no free-text or corpus content. If storing it needs a new table, include it in B2a's migration.
5. **Lock hold measurement.** Report lock hold time and query plan for ranking under the control lock at representative fixture volume in the B2b verification record.
6. **Sensitive and `escalate_only` content** stays excluded at both publication and retrieval until the owner decides (section 6).
