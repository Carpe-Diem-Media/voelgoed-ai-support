## Orchestrator addendum (accepted with changes, 2026-11-26)

The orchestrator reviewed this plan against `docs/plans/VGAS-003_PLAN.md` (the Editorial UI section, the accepted changes, and the AC1/AC3 UI and portability row), AGENTS.md and A-011. The plan is accepted with these changes, which take precedence over the sections above.

1. **Two serial PRs instead of one PR with checkpoints.** The first LiveView socket is a new security boundary, so it gets its own reviewed and merged candidate. Both PRs stay behind the existing default-off staff gate, so a merged C1 exposes no partial workflow.
   - **C1, transport and reads:** the C1 section above, plus the read contracts (item 2), `self_approval_required`, staff headers and CSP, assets, the read-only screens with their empty, error and denial states, the auth and transport tests, and Hallmark and accessibility evidence for the C1 screens. File: `docs/plans/VGAS-003C1_VERIFICATION.md`.
   - **C2, forms and portability:** the C2 section above, the remaining verification, final Hallmark and accessibility evidence for the mutating screens, and the runbook. File: `docs/plans/VGAS-003C2_VERIFICATION.md`. C2 branches from merged C1.
2. **Read contracts approved.** The accepted VGAS-003 plan already requires `/staff/knowledge` to list permitted collections and articles. Named, bounded `list_collections`, `list_articles(collection_id)` and `list_revisions(article_id)` actions implement that requirement, with no new business rule. They come with the extended `read_revision`, which adds safe per-locale index status, viewer action hints and `self_approval_required`.
   - **Scope:** filter by scope before paging. Use stable ID ordering and a page size of at most 50, with safe projections only.
   - **Who sees what:** ADMIN sees collection metadata only. Content lists require actual editor or reviewer membership.
   - **No migration.** If one turns out to be needed, stop and report.
3. **Session lifetime.** The socket must recheck `StaffAccess` on every event, navigation and refresh, and disconnect when the session deadline passes. Immediate revocation of an already-connected tab, and of a captured cookie, after an ordinary sign-out stays an owner decision before staff use, recorded under VGAS-9. Document the bounded lifetime in the verification record.
4. **No dependency or build changes.** `mix.exs` and `mix.lock` stay unchanged; the plan's `git diff --exit-code` check enforces this. Leave the esbuild and Tailwind pins alone. Serve the locked Phoenix and LiveView JavaScript from their packages' `priv/static`, plus hand-written tokenized CSS.
5. **Hallmark.** Follow the installed skill's new-page or app-screen workflow. If an authenticated render or another required check cannot run, record the exact gap and do not claim Hallmark verification. The owner must waive the gap explicitly before the gate counts as met.
6. **Process.**
   - Commit this plan with its addendum as C1's first commit.
   - Run database checks only on the disposable pgvector runner at port 55434.
   - Use Phoenix ports from the assignment, and stop servers when done.
   - Run the forced compiles at `+S 1` and `+S 2`.
